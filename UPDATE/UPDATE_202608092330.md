# Engineering Update: Phase 5 Live/Simulator Execution Parity

**Recorded:** 2026-08-09 23:30:35 (UTC+08:00)

## Summary

Phase 5 core execution parity is complete. Training diagnostics and the
standalone backtester now use one deterministic execution engine that represents
the live policy for closed-candle inference, next-open entry, one-position
locking, opposite-signal reversal, ATR TP/SL, break-even protection, the 24-bar
time stop, conservative same-bar conflicts, and transaction spread.

Live execution was corrected to infer from the most recently completed candle
instead of the newly forming candle. The locked six-month final test remains
unopened and the standalone backtester now refuses to run unless an explicit
Phase 6 unlock flag is supplied.

## Why These Changes Were Necessary

### Why Live Inference Must Exclude the Forming Candle

The live loop runs a few seconds after a new five-minute candle opens. It
previously requested data beginning at MT5 position zero, which includes that
newly forming candle. Training sequences end on a fully completed signal candle
and their trade enters on the following candle's open.

Using two seconds of an unfinished live candle creates a training/live timing
mismatch and unstable indicators. Live preprocessing now starts at MT5 position
one, ensuring every input candle is complete and the resulting signal trades at
the current candle's price.

### Why One Shared Execution Engine Was Added

The training script and standalone backtester previously contained separate
trade loops. They had already drifted from live behavior: both ignored reversal
signals and break-even management, while using different output structures.

`execution_simulator.py` is now the authoritative candle-level execution engine.
Both historical paths call it, making later rule changes testable in one place
and preventing silent differences between calibration diagnostics and final
backtesting.

### Why Opposite Signals Reverse at the Current Open

With the live position lock enabled, a same-direction signal is ignored. An
opposite signal closes the existing position and opens the new direction. The
old simulator ignored every signal while a position was open, which materially
understated turnover and changed the strategy being evaluated.

The simulator now processes the new decision at the current bar open, closes an
opposite position, and opens the reversal at that same observable price. It does
not pyramid same-direction signals.

### Why Break-Even Is Included

Live execution moves the stop to entry plus or minus 0.05 after price reaches 60%
of the three-ATR target distance. Historical tests previously left the original
two-ATR stop in place for the entire trade.

The simulator now activates the same break-even rule and records whether the
protection was active at exit. Candle data cannot reveal the ordering of every
tick inside a bar, so TP/SL conflicts remain deliberately conservative: the stop
is selected when both barriers appear in the same candle.

### Why the 24-Bar Time Stop Was Added to Live Execution

Training labels judge a trade only across the next 24 candles, and historical
testing already expected a 24-bar exit. Live positions previously had no matching
time stop and could remain open far beyond the behavior the model learned.

Live execution now closes a strategy-owned position after 24 five-minute bars.
This restores consistency between the label horizon, simulator, and broker-side
behavior.

### Why Strategy Ownership Filtering Was Required

Automated break-even, reversal, weekend, and time-stop actions must never manage
manual positions or trades opened by another strategy on the same symbol.

Live position queries now retain only positions carrying this strategy's magic
number. This safety boundary was necessary before adding automated time-stop
closure and also improves the safety of existing management functions.

### Why Signal ATR Is Stored Explicitly

A decision formed on candle `t` executes on candle `t+1`. TP and SL distances
must use ATR from candle `t`, not a partially formed entry candle or an
off-by-one row selected indirectly.

Preprocessing now attaches `signal_atr` to each execution row. The simulator
requires that field, making timing explicit and causing malformed inputs to fail
instead of silently using the wrong volatility value.

### Why Recorded Spread Replaces the Fixed Approximation

Both datasets include historical spread in broker points. The earlier simulator
subtracted a fixed price penalty of 0.20 from every completed trade. That was a
reasonable conservative approximation but ignored periods where execution was
cheaper or more expensive.

The engine now converts recorded spread using the configured XAUUSD point size
and applies it according to bid-based OHLC behavior: Buy trades pay the entry
spread and Sell trades pay the exit spread. The fixed 0.20 penalty remains a
fallback if recorded spread is unavailable or invalid.

### Why the Standalone Backtester Is Explicitly Locked

`backtest_simulator.py` directly loads the six-month final dataset. Accidentally
running it during simulator development would expose final-test performance and
weaken the validity of Phase 6.

It now exits before preprocessing unless `--unlock-final-test` is supplied. A
direct safety check confirmed the default message and did not evaluate the final
period.

### Why Model A Hidden Size Is Inferred

The standalone backtester hard-coded a hidden dimension of 64, while the
production Optuna run selected 128. That would prevent the saved checkpoint from
loading or encourage someone to alter the architecture manually.

The loader now reads the hidden dimension from the saved LSTM weight shape before
constructing Model A. This ties inference architecture to the actual checkpoint.

## Implemented Files

- `execution_simulator.py`: shared deterministic one-position execution engine.
- `strategy_config.py`: shared break-even, reversal, ownership-policy defaults,
  point size, and recorded-spread behavior.
- `gemini-training.py`: explicit signal ATR alignment and shared execution engine
  for calibration/final diagnostics.
- `backtest_simulator.py`: shared engine, recorded spread, inferred Model A size,

- `live_execution.py`: completed-candle inference, shared threshold comparison,
  strategy-position filtering, and 24-bar time stop.
- `tests/test_execution_simulator.py`: deterministic parity tests.

## Effect on Phase 4 Threshold

The production threshold remains `0.26`. Phase 4 selected it using the isolated
calibration tail's accepted-signal precision and Wilson lower bound, not trading
profit. Phase 5 changes the economic diagnostic simulation but does not alter
Model A predictions, Model B probabilities, or the statistical threshold rule.
Therefore the threshold does not need to be retrained solely because of this
execution-engine correction.

## Remaining Realism Limits

The candle simulator cannot reproduce tick order, order rejection, latency,
slippage beyond spread, broker stop-level restrictions, partial fills, or weekend
gaps exactly. These items require MT5 paper/strategy testing and belong to live
hardening rather than being inferred from OHLC candles.
