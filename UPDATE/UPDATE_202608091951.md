# Engineering Update: Leakage-Safe Classification Training Foundation

**Recorded:** 2026-08-09 19:51:11 (UTC+08:00)

## Summary

This update establishes a safer and more reproducible foundation for training the
classification-based XAUUSD trading system. The live system remains based on the
Model A CNN-LSTM-Attention classifier and Model B TCN gatekeeper trained by
`gemini-training.py`. The separate regression experiment is not being promoted
to live execution at this stage.

## Dataset Boundary Verification

The replacement datasets were checked before changing the training pipeline:

- Development dataset: 141,768 candles from 2023-11-01 00:00 to 2025-10-31 00:00.
- Final test dataset: 34,324 candles from 2025-11-03 01:00 to 2026-04-29 23:55.
- Duplicate timestamps: none.
- Overlapping timestamps: none.

The final six-month dataset is now chronologically separated from development
data and can serve as an untouched out-of-sample test, provided it is not used
for repeated tuning or threshold selection.

## Implemented Changes

### 1. Automated Dataset Validation

Added `data_validation.py` to reject training runs when input data contains:

- Missing required OHLCV columns.
- Invalid or duplicate timestamps.
- Non-chronological rows.
- Missing, infinite, or non-positive price values.
- Invalid OHLC relationships.
- Negative tick volume.
- Intervals shorter than five minutes or timestamps off the M5 grid.
- Any timestamp overlap between development and final test datasets.

Normal market-closure gaps are counted for audit purposes but are not treated as
errors.

### 2. Shared Strategy and Model Configuration

Added `strategy_config.py` as the central source for:

- Feature names and ordering.
- Lookback window: 60 candles.
- Triple-barrier horizon: 24 candles.
- Reproducibility seed: 42.
- Take-profit distance: 3 ATR.
- Stop-loss distance: 2 ATR.
- Gatekeeper threshold: 0.52.
- Backtest spread penalty: 0.20.

`gemini-training.py`, `backtest_simulator.py`, and `live_execution.py` now read
these shared settings. This removes the previous live/backtest mismatch where
live execution used a 3 ATR stop but training used a 2 ATR stop.

### 3. Leakage-Safe Chronological Development Splits

The classification development dataset is now divided chronologically into:

- 70% for Model A fitting.
- 15% for Model A hyperparameter selection and early stopping.
- 15% as a later held-out period for Model B meta-label generation.

An 84-candle embargo, covering the 60-candle lookback and 24-candle target
horizon, separates the development periods. The final six-month dataset remains
separate from all three periods.

The feature scaler is now fitted only on the Model A fitting period. Model A
validation, Model B meta-learning, and final test features are transformed with
that already-fitted scaler.

### 4. Safer Model B Gatekeeper Training

Previously, Model B labels were generated from Model A predictions over samples
that included Model A training data. This produced optimistic correctness labels.

Model B labels are now generated only from the later held-out meta-learning
period. That period is then divided chronologically into Model B training and
validation subsets with an additional embargo. Model B checkpoint selection and
early stopping now use validation loss rather than training loss.

### 5. Signal and Execution Timing Alignment

The original triple-barrier labels were anchored to a future candle close while
the backtester entered at that candle's open. This created a target/execution
timing mismatch.

The corrected process is:

1. Model features end at candle `t` close.
2. The simulated trade enters at candle `t+1` open.
3. Profit and stop barriers are anchored to that entry price.
4. ATR is taken from the completed signal candle.
5. Future highs and lows determine which barrier is reached first.

Sequence labels and backtest metadata now follow this same timing convention.

### 6. Reproducibility

- NumPy and PyTorch use the shared seed.
- Optuna now uses a seeded TPE sampler.
- Model dimensions, features, horizon, thresholds, and risk settings are read
  from shared configuration.

## Important Behavior Change

The live default stop-loss multiplier is now 2 ATR so it matches the classification
labels and backtest. Existing runtime Telegram changes can still override the
in-memory value while the bot is running.

No new model artifacts have been trained or deployed as part of this update.
