# Changelog & System Updates

## [Latest Update] - System Architecture & Risk Management Upgrades

### 🚀 New Features
* **Dynamic Break-Even Protocol (`apply_breakeven`)**: Implemented an active trade management system that monitors floating profit every 0.5 seconds. Automatically moves the Stop Loss to the Entry Price plus a safety buffer once the price reaches a dynamic percentage (milestone) of the Take Profit distance.
* **Live Risk Management via C2 (Telegram)**: Added real-time control over risk parameters without requiring a script restart.
  * Added `/sl` and `/tp` commands to dynamically adjust ATR multipliers.
  * Added `/breakeven`, `/betrigger`, and `/bebuffer` commands to tune the Break-Even state machine.
* **Advanced Status Readout**: Updated the `/status` command to include live target multipliers (TP/SL) and the current Break-Even configuration metrics.

### 🐛 Bug Fixes & Stability
* **Timezone Offset Collision Fixed**: Resolved a critical bug where Python's `datetime.fromtimestamp()` appended the local OS timezone offset to the broker's raw UNIX timestamp. Replaced with `datetime.fromtimestamp(..., timezone.utc)` to ensure the Friday Flat protocol triggers accurately based on MT5 server time.
* **Polling Window Network Lag Resolved**: Widened the AI inference execution window from 1 second (`2 <= seconds_past_candle < 3`) to 4 seconds (`2 <= seconds_past_candle < 6`). This prevents API network lag (e.g., Telegram connection delays) from causing the system to miss the execution window for new M5 candles. Adjusted the subsequent sleep cycle to 5 seconds to prevent duplicate executions.

### 🔍 Logging & Auditability Upgrades
* **MT5 Server Time Injection**: Created the `get_server_time_str()` helper function. The exact interbank MT5 server time is now injected into all system logs (`trading_bot.log`) and Telegram receipts for:
  * Order Execution (Entry)
  * Trade Closure (Exit/Reason)
  * AI Signal Output Generation
