# Engineering Update: Phase 6 One-Time Locked Final Evaluation

**Recorded:** 2026-08-09 23:47:44 (UTC+08:00)

## Executive Decision

Phase 6 is complete. The frozen classification system failed its locked
six-month evaluation and is rejected for paper or live deployment in its current
form.

The evaluation was executed exactly once using the committed Phase 5 execution
policy, production Model A and Model B checkpoints, frozen scaler, and frozen
Model B threshold of `0.26`. No retraining, refitting, threshold adjustment, or
post-test tuning occurred.

The gated strategy lost `$620.61` at the default fixed `0.01` lot size, a
`-6.21%` return on `$10,000`, with profit factor `0.884`, maximum drawdown
`-7.63%`, and Sharpe ratio `-2.81`. These economic results are sufficient to
reject deployment regardless of the higher aggregate classification accuracy
created by predicting Hold more often.

## Why a One-Shot Evaluator Was Added

Repeatedly evaluating the six-month dataset while modifying thresholds,
features, losses, or execution settings would convert the final test into a
validation set. A dedicated `final_evaluation.py` runner therefore creates a
durable lock before loading the final labels and refuses to execute if the lock
already exists.

The lock records:

- Start and completion timestamps.
- Git commit being evaluated.
- SHA-256 fingerprints of the evaluator, training pipeline, execution engine,
  models, scaler, threshold artifact, and final dataset.
- A policy forbidding retraining and post-test tuning.
- The final result location and selected summary metrics.

This makes the reported result attributable to an exact frozen system rather
than a moving experiment.

### Ungated Model A

Model A produced 33,933 Buy/Sell signals from 33,939 sequences, or `99.98%`
signal coverage. It predicted Hold only six times.

| Class | Precision | Recall | F1 |
|---|---:|---:|---:|
| Hold | 100.00% | 0.04% | 0.08% |
| Buy | 30.17% | 51.38% | 38.01% |
| Sell | 31.62% | 56.58% | 40.57% |

- Accuracy: 30.95%.
- Macro F1: 26.22%.
- Prediction distribution: Hold 6, Buy 16,034, Sell 17,899.

The near-absence of Hold predictions is a critical failure. Model A did not learn
a selective three-class decision policy; it effectively became a continuously
active Buy/Sell classifier. The low Hold class weight in focal-loss training is a
likely contributor, but this final dataset must not be used to tune a replacement.

### Hierarchical Model A + Model B

Model B accepted 10,902 of Model A's signals. This represents:

- 32.13% gate acceptance among Model A signals.
- 32.12% final signal coverage across all sequences.
- 34.96% accepted directional precision.

| Class | Precision | Recall | F1 |
|---|---:|---:|---:|
| Hold | 47.12% | 74.75% | 57.80% |

- Accuracy: 43.21%.
- Macro F1: 35.90%.
- Weighted F1: 38.95%.
- Final prediction distribution: Hold 23,037, Buy 6,722, Sell 4,180.

The improved accuracy is not evidence of a profitable system. It is driven
mainly by Model B converting many weak Buy/Sell predictions into Hold. Accepted
directional precision declined from `40.83%` in the calibration period to
`34.96%` in the final period, a deterioration of 5.87 percentage points.

## Why No Threshold or Model Changes Were Made

The final result is not a new tuning signal. Changing threshold 0.26, focal-loss
weights, features, or execution rules and then measuring this same period again
would invalidate the test.

The correct response is to reject this frozen candidate. Any redesigned
classifier or regression challenger must be developed using development data
only and evaluated on a newly reserved period that was not used to motivate its
design.

## Recommended Next Plan

1. Commit the Phase 6 evaluator, lock, and tracked update record without changing
   the frozen models or threshold.
2. Do not run `final_evaluation.py` again and do not use the old six-month period
   as a test set for a redesigned classifier.
3. Obtain a new non-overlapping forward dataset beginning after 2026-04-29 and
   reserve it before challenger development.
4. Diagnose Model A using development/validation data only, focusing on the Hold
   collapse and signal coverage.
5. Build the regression challenger offline with chronological purges and economic
   metrics; do not promote based on reconstructed-price R-squared.
6. Freeze classifier-replacement and regression-challenger designs before opening
   the new reserved period.
7. Promote only a candidate with positive net expectancy after recorded spread,
   acceptable drawdown, sufficient trades, and stable forward behavior.
